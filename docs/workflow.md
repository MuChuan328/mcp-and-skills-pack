# 逆向工作流（与 AI 协作版）

> 目标：让每一步都有证据、可复现、可交接，而不是「试出来的结论」。

## 0. 立项

- 目标应用、版本、来源
- 授权范围（自有 / 客户授权 / CTF）
- 预期产出：接口复现脚本 / 漏洞报告 / 兼容性结论

## 1. 取证

- 抓包（Charles / mitmproxy / Wireshark）
- 日志（logcat、崩溃栈）
- 样本（APK/IPA/so/JS bundle）与哈希

## 2. 静态

- jadx 反编译，先看 `AndroidManifest`、网络层、签名类
- 关键字符串、常量、URL 交叉引用
- 加固/混淆判断：见 `../android-reverse-toolkit/docs/unpack-checklist.md`

## 3. 动态

- Frida spawn + hook 关键函数，打印入参与返回值
- 需要改逻辑时先备份原始样本
- 反调试/反虚拟机：先确认检测点，再决定是否绕过

## 4. 复现

- 用最小 Python 脚本复现一次请求
- 固定随机数、时间、设备参数，保证可重复
- 记录失败分支（4xx/5xx/风控）与重试策略

## 5. 记录

每个目标一份记录：

```
目标 / 版本 / 加固
入口 / 关键类 / 关键函数
参数与签名表
复现脚本路径
未解决问题
```

## 与 AI 协作的注意事项

1. 让 AI 先读证据（日志、反编译片段），再给结论；
2. 每个结论要求给出行号/请求/返回码；
3. 不让 AI 猜密钥、猜算法；
4. 敏感数据脱敏后再贴给模型。
